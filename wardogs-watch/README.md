# WARDOGS Watch

게임 화면에 보이는 **킬 피드만 읽어서** 핵이 의심되는 플레이어를 실시간으로 추려 주는 도구입니다.

> **판정기가 아닙니다.** 점수는 "관전해 볼 만한 사람" 목록일 뿐 핵이라는 증거가 아닙니다.
> 결과로 특정인을 공개적으로 지목하지 말고, 게임 안 신고 기능으로 신고할 때 참고하세요.

```
모니터 화면 캡처 (OBS와 같은 방식)
   → 킬 피드 영역 글자 인식 (RapidOCR)
   → "누가 누구를 죽였는지" 이벤트로 정리 (같은 줄 중복·오인식 제거)
   → 로비 전체와 비교해 의심 점수 계산
   → 브라우저 대시보드 (보조 모니터 / 휴대폰)
```

## 계정 안전 원칙

워독스는 커널 레벨 안티치트(Elytra)를 씁니다. 그래서 이 도구는 핵 프로그램이 쓰는 방식을 **전부 피합니다.**

| 하지 않는 것 | 대신 하는 것 |
|---|---|
| 게임 메모리 읽기, 패킷 가로채기, 코드 주입 | 모니터에 이미 그려진 화면만 복사 (윈도우 Desktop Duplication / GDI, OBS 디스플레이 캡처와 같은 기능) |
| 게임 화면 위에 정보 그리기 (오버레이) | 별도 브라우저 창에 표시 (보조 모니터나 휴대폰 권장) |
| 키보드·마우스 자동 입력 | 없음 |

그래도 외부 프로그램 사용에 대한 판단은 게임 약관을 따릅니다. **워독스 이용약관(EULA)의 외부 프로그램 조항은 직접 확인하세요.**

## 설치 (윈도우)

1. [Python](https://www.python.org/downloads/) 3.10~3.12 설치. 설치 첫 화면에서 **Add python.exe to PATH** 체크
2. 이 폴더의 `install.bat` 실행 (처음 한 번, 몇 분 걸림)
3. 게임 화면 모드를 **테두리 없는 창 모드(Borderless / 창 전체화면)** 로 설정
   전체화면 독점 모드에서는 캡처가 검은 화면으로 나올 수 있습니다.

## 처음 한 번: 킬 피드 위치 지정

1. 게임을 켜고 킬 피드가 여러 줄 쌓였을 때 `calibrate.bat` 실행
   (또는 그런 순간의 스크린샷을 찍어 두고 `.venv\Scripts\python -m wdwatch calibrate --image 스크린샷.png`)
2. 화면이 뜨면 킬 피드 영역을 **위아래로 조금 넉넉하게** 드래그 → Enter
3. 잘 읽히는지 확인: `.venv\Scripts\python -m wdwatch snap`
   ```
   읽힌 글자: ['Ghost-Wolf(0.98)', 'tanker99(0.99)', ...]
     Ghost-Wolf  →  tanker99
   ```
   죽인 사람과 죽은 사람이 반대로 나오면 `config.json`의 `killer_side`를 `"right"`로 바꾸세요.
4. `config.json`의 `"my_name"`에 내 닉네임 입력 (내가 죽은 순간을 알아내는 데 씀)

### (선택) 아이콘 등록: 헤드샷, 차량 킬

킬 피드에 헤드샷 표시 아이콘이 있다면 등록해야 **헤드샷 비율 신호**가 켜집니다.

```
.venv\Scripts\python -m wdwatch calibrate --icon headshot --image 헤드샷킬이_보이는_스크린샷.png
.venv\Scripts\python -m wdwatch calibrate --icon vehicle  --image 차량킬이_보이는_스크린샷.png
```

킬 피드 영역이 3배로 확대돼서 뜨면 아이콘 하나만 테두리에 딱 맞게 드래그하세요.
`vehicle`, `explosive` 태그가 붙은 킬은 조준 관련 신호에서 빠집니다 (헬기·차량·폭발물 킬이 에임봇처럼 보이지 않게).

## 실행

| 파일 | 하는 일 |
|---|---|
| `start.bat` | 실시간 분석 시작. 대시보드가 브라우저에 자동으로 열림 |
| `start.bat --lan` | 같은 와이파이의 휴대폰에서도 대시보드 보기 (콘솔에 주소가 나옴) |
| `demo.bat` | 게임 없이 가짜 킬 피드로 시험 (40명 중 `NightOwl_K`가 핵 역할) |
| `python -m wdwatch video 녹화.mp4` | 녹화 영상 분석 (설정 튜닝용) |

새 매치를 시작할 때 대시보드의 **통계 초기화**를 누르세요. 3분 동안 킬이 하나도 없으면 매치가 끝난 것으로 보고 자동으로 초기화합니다.
분석 기록은 `logs/session-날짜.jsonl`에 남습니다.

## 판단 기준

모든 기준은 **같은 로비 사람들과 비교**합니다. 표본이 적으면 판단하지 않습니다.
값은 `config.json`의 `detector` 항목에서 바꿀 수 있습니다.

| 신호 | 기준 (기본값) | 점수 | 노리는 핵 |
|---|---|---|---|
| 순간 다중 킬 | 2초 안에 3명 이상 (`burst_window`, `burst_kills`) | 한 번에 15점, 4명 이상이면 25점 (최대 45점) | 에임봇 순간 조준, 패킷 조작 |
| 킬 속도 | 최근 10분 킬 수가 로비 중앙값보다 크게 높음 (강건 z-점수 3.5 이상, 8킬 이상, 분당 1.5킬 이상) | 15~35점 | 전반적인 핵 |
| 헤드샷 비율 | 12킬 이상에서, 로비 평균(본인 제외)보다 30%p 이상 높고 60% 이상. 표본이 적으면 로비 평균 쪽으로 당겨서 계산 | 20~35점 | 에임봇 |
| 연속 킬 | 안 죽고 15킬 | 10점 | 약한 참고 신호 |
| 나를 여러 번 죽임 | 2번 이상 | 0점 (정보만 표시) | - |

**50점 이상 = 높음, 25점 이상 = 중간.** 높음이 되는 순간 알림이 뜹니다.

### 킬을 정확히 세는 방법

- 킬 피드 한 줄은 몇 초 동안 남아 있어서, 이미 센 줄은 다시 세지 않습니다.
- 한 번만 읽힌 줄은 오인식일 수 있어서 **서로 다른 OCR 결과에서 두 번** 읽혀야 킬로 인정합니다.
- OCR이 같은 닉네임을 조금씩 다르게 읽어도(`NightOwl_K` / `Night0wl_K`) 한 사람으로 묶습니다.
  단 `Player123`과 `Player124`처럼 숫자만 다른 이름은 다른 사람으로 둡니다 (잘못 합치면 멀쩡한 사람의 킬이 부풀기 때문).

## 한계

시뮬레이션 결과입니다 (40명 로비, 15분, 200판. 실제 게임 데이터가 아님).

| 플레이어 유형 | 높음 | 중간 | 낮음 |
|---|---|---|---|
| 일반 유저 (분당 0.4킬, 헤드샷 25%) | 0% | 0% | 100% |
| 실력 좋은 일반 유저 (분당 1.2킬, 헤드샷 45%) | 0% | 16.5% | 83.5% |
| 티 안 내는 핵 (분당 1.5킬, 헤드샷 65%) | 5.5% | 32.5% | 62% |
| 대놓고 쓰는 핵 (분당 2.5킬 이상, 순간 다중 킬, 헤드샷 80%) | 거의 항상 높음 | | |

- **대놓고 쓰는 핵은 잘 잡히고, 티 안 내는 에임봇은 '중간' 정도, 월핵만 쓰는 사람은 거의 못 잡습니다.** 월핵은 조준이 사람 실력 그대로라 킬 기록에 이상한 숫자가 남지 않습니다.
- 실력 좋은 사람이 '중간'으로 뜰 수 있습니다. 그래서 점수만으로 판단하지 말고 관전이나 킬캠으로 직접 확인하세요.
- 100명 매치에서 킬 피드가 빠르게 지나가거나 일부 킬만 표시되면 누락이 생깁니다. 누락은 모든 사람에게 비슷하게 생기므로 로비 비교에는 영향이 적습니다.
- **아직 실제 워독스 화면으로는 시험하지 못했습니다.** 킬 피드 글꼴·색·배경에 따라 인식률이 달라질 수 있어서, 실제 스크린샷으로 기준을 다시 맞춰야 합니다.

## (선택) OBS로 증거 영상 자동 저장

녹화는 OBS가 그래픽카드 인코더로 하므로 게임 성능에 거의 영향이 없습니다.

1. OBS 28 이상 설치 → 설정 → 출력 → **리플레이 버퍼 사용** 체크 (30초 정도)
2. OBS 도구 → **WebSocket 서버 설정** → 서버 사용 체크, 비밀번호 확인
3. `config.json`
   ```json
   "obs": { "enabled": true, "password": "OBS에서 본 비밀번호", "clip_on_my_death": true, "clip_on_high_alert": true, "delay_seconds": 8 }
   ```

내가 죽거나 누군가 '높음'이 되면 8초 뒤(킬캠까지 담기게) 리플레이 버퍼가 저장됩니다.

## 성능

- 킬 피드 영역만 캡처하고, OCR은 CPU 스레드 2개로 제한합니다 (`ocr_threads`).
- 개발 환경(클라우드 CPU)에서 OCR 한 번에 약 100~250ms였습니다. 게임이 끊기면 `capture_fps`를 2~3으로 낮추세요.

## 주요 설정 (`config.json`)

| 키 | 기본값 | 설명 |
|---|---|---|
| `monitor` | 1 | 게임이 나오는 모니터 번호 |
| `killfeed` | 오른쪽 위 | 킬 피드 영역 (화면 대비 비율). `calibrate`로 설정 |
| `killer_side` | `left` | 킬 피드 한 줄에서 죽인 사람이 있는 쪽 |
| `my_name` | 빈칸 | 내 닉네임 |
| `capture_fps` | 4 | 초당 캡처 횟수 |
| `confirm_hits` | 2 | 킬로 인정하기 위해 필요한 OCR 횟수 |
| `icon_templates` | 없음 | `{"headshot": "templates/headshot.png"}` |
| `exclude_tags` | vehicle, explosive | 조준 신호에서 뺄 킬 종류 |
| `dashboard_port` | 8765 | 대시보드 주소 포트 |

## 개발

```
wdwatch/
  capture.py    화면·영상에서 킬 피드 영역 잘라 오기
  ocr.py        글자 인식 (RapidOCR)
  killfeed.py   글자 상자 → 킬 줄 → 새 킬 이벤트 (중복·오인식 제거)
  names.py      닉네임 오인식 묶기
  icons.py      헤드샷·차량 아이콘 찾기
  analysis.py   의심 신호와 점수
  pipeline.py   전체 흐름
  dashboard.py  로컬 웹 대시보드
  obs.py        OBS 리플레이 버퍼 저장
  demo.py       가짜 킬 피드 (데모·테스트용)
  cli.py        명령어
```

테스트: `pip install pytest` 후 `python -m pytest tests`
(실제 OCR 테스트 포함 약 30초)
